\section{Introduction}
\label{sec:thesis}

Long reasoning turns memory into the deployment bottleneck. Under full attention~\cite{transformer}, every generated token adds to the key--value (KV) cache, so a model that reasons for 100K tokens must also store 100K tokens of history. We call such models, whose memory grows with reasoning, \emph{growing-history} models. In data centers, their caches consume limited high-bandwidth memory (HBM), cutting the number of requests each accelerator can serve and raising serving costs~\cite{pagedattention}.

For many deployments, a smaller cache is not enough: the cache must be fixed. On edge devices, robots and vehicles must reserve limited memory for perception, planning, and control~\cite{edge_llm}; dedicated chips go further and fix on-chip capacity at design time. A growing cache forces a choice between reserving space for the longest possible trace and cutting reasoning short when memory runs out. A fixed history budget makes that allocation predictable: the same memory serves a sequence at 4K or 256K tokens. What these deployments need is determinism, not only efficiency.

Recent architectures shrink this cache aggressively: multi-head latent attention (MLA) compresses each cached token~\cite{deepseekv2}; hybrids such as Qwen3.5 and Kimi Linear build most layers from Gated DeltaNet (GDN) or Kimi Delta Attention (KDA) and keep full attention in only one layer in four~\cite{qwen35,kimilinear}; DeepSeek Sparse Attention (DSA) reads only a subset of entries~\cite{deepseekv32}, and the compressed sparse attention (CSA) of DeepSeek-V4 stores fewer~\cite{deepseekv4}; and KV quantization methods such as KIVI use fewer bits per entry~\cite{kivi}. Each lowers the cost of a cached token, but the cache still grows with every token the model reads or writes. Shrinking the growth rate moves the memory wall further out; it does not remove it.

\emph{Bounded-state} models already provide this determinism in history storage. Recurrent and state-space models compress history into fixed-size states~\cite{mamba,rwkv7,xlstm}, and sliding-window attention, alone or in recurrent hybrids, keeps only recent tokens~\cite{longformer,recurrentgemma,samba}. None that we evaluate delivers usable reasoning: across 16 bounded-state models up to 14B parameters, none exceeds 18.8\% on AIME 2024--2026 (Section~\ref{sec:capability}). Inference-time eviction can also cap the cache of a growing-history model by keeping attention sinks, recent tokens, or tokens that drew high attention~\cite{streamingllm,h2o,snapkv}, but the model was never trained to reason with only what remains.

Long reasoning keeps returning to details stated thousands of tokens earlier: a definition, a constraint in the problem statement, an intermediate result. A sliding window forgets such a detail once it scrolls out; a recurrent state keeps only a compressed summary in which individual details blur together~\cite{repeatafterme}. The question becomes: \emph{can a model keep the distant details that later reasoning needs within a fixed memory, so that constant memory no longer costs reasoning ability?}

EdgeRock addresses this with \emph{Rock Memory Anchors} (RMA). Like a rock anchor that pins a structure to bedrock, RMA pins critical details in place. Each \emph{anchor} is a learned key--value record held in a fixed-size \emph{anchor bank}. Recurrent state summarizes the evolving context, local attention covers the most recent 1,024 tokens, and RMA keeps the most valuable details from earlier context. A learned writer produces a candidate record for each token, and a learned scorer rates it. Once 256 candidates have accumulated, each KV group compares them with the records already in its bank, keeps the highest-scoring 1,024 records, and discards the rest. Kept records stay separate and unchanged, so any later token can attend to them directly, long after their source has left the window. Local attention and RMA together hold attention KV at 72\,MiB per sequence, however long the model reasons; with recurrent state, everything a sequence must store to continue, its \emph{persistent history}, stays at 97.76\,MiB in the batch runtime.
